## 原始问题与修复

首轮正常配置检查通过后，独立复核发现两条 P1 问题。早期结果不足以放行，记录如下，避免以通过数掩盖反例。

1. **命名 translator 绕过。** 初版只检查默认 `translator/` 的三个无学习开关。将实际组件改成 `table_translator@remember` 并在 `remember/` 下启用学习后，程序仍报告 `learning:false`，却创建了 `wubi86.userdb`；重复选择“您好”使其成为首候选。
2. **未批准的初始方案。** 初版在创建会话后才切到五笔。如果额外方案位于 `default.schema_list` 首位，会话创建已先实例化该方案。仅启动、查询、退出即可生成 `pinyin_simp.userdb`。

修复采用两层验证：Rime 初始化和维护前核对允许的目录内容、源文件 SHA-256、固定隐私补丁及符号链接；部署后、创建会话前核对实际组件、词典、方案依赖、初始列表与快捷键跳转目标。第一批只支持固定离线方案，拒绝任意用户脚本和额外配置。

自动检查包含上述两条原始反例，以及修改学习补丁、Lua 文件、缓存中的过滤器、快捷键跳转、词典改向与符号链接等相邻入口。源文件被修改时，还验证拒绝后目录文件哈希完全不变。

## 构建入口一致性

Python 辅助脚本和 CMake 均在 C++ 编译前校验受信文件清单；普通构建不会自动更新清单。开发者确需变更批准内容时，须先审查，再显式运行 `generate_policy.py --update` 并重建验证。

补充实测使用 CMake 3.28.3：正常 Linux 构建成功；在隔离副本中篡改五笔学习补丁后，CMake 构建以退出码 2 失败，产生 0 个 `.o` 文件。证据见 [tests/results-cmake.json](../tests/results-cmake.json)。**没有运行 Windows 编译或系统接入测试。**
