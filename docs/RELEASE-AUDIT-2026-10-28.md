## 安装权限边界修复

初轮发现：管理员安装/回滚直接执行可由普通用户写入的旧目录 helper，且自由选择的目录可以成为机器 COM DLL 的加载路径。隔离、非提权复现中，更改旧 helper 后回滚仍执行该程序；这证明信任边界缺失，没有进行系统提权利用。

本轮改为分离机器程序和用户数据：

- 可执行程序、DLL 和机器 COM 路径固定在 Windows 的受保护 Program Files 下。校验覆盖目录形状、祖先、所有者、写入/删除权限、重解析点及整个运行时目录。管理员临时 payload 同样使用受保护祖先目录。
- 用户可以选择本地词库目录。独立普通用户载荷仅提取 YAML、许可和说明，不包含 exe/dll，不执行外部程序，不修改系统注册。载荷自身检查 token，高权限或无法确定权限均在任何路径操作前返回 40。
- 回滚仅使用当前可信 helper。存在旧 profile 时保留其原注册；恢复新身份的旧受保护版本时先验证路径。任何路径都不会执行旧目录的程序。
- 旧文件清理另有权限：只接受 YANVY/版本目录形状并检查整个受保护目录树；该许可不允许执行旧程序或将任意旧路径重新注册为 COM。清理只删除明确文件，保留未知文件。
- 用户数据清理由原普通用户执行。安装失败的载荷回滚只接受本包版本和源码提交完全匹配的 marker；兼容旧版的清理 helper 则接受受限的 YANVY 版本 marker，只使用从仓库生成的固定文件清单。两者拒绝目录联接、保留未知文件，不递归删除用户选择的目录；后者还持有不允许删除共享的目录句柄，并按文件句柄删除，避免清理过程中重定向路径。

隔离事务验证同时发现并修复了两个实际失败路径：预创建的空机器目录曾被误判为非空；引擎检查生成的固定缓存曾在回滚后残留并阻止重试。前者已通过新夹具，后者另以真实 librime 的注册失败和同路径重试验证。

只保护子目录不够：父目录的删除/改名权限也能影响安全性，参见 [Microsoft 文件删除权限](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-deletefile)。新的运行时校验覆盖该边界。普通用户数据检查不是针对拥有同一用户目录写权限进程的并发沙箱；它不获得管理员权限。

## 0.1.1 托盘菜单修复

原托盘窗口由不感知 DPI 的线程创建，右键处理又丢弃了 NOTIFYICON_VERSION_4 回调坐标、无条件采用图标矩形中心。隐藏图标面板及缩放场景下，这会使弹出菜单与点击位置不一致。

本轮在创建托盘 owner 窗口之前，为专用线程设置 Per-Monitor V2；菜单优先采用回调提供的有符号屏幕坐标，键盘调用的 `(-1,-1)` 才回退到图标矩形或光标位置。不手工乘除 DPI 倍率，也不改变引擎其他线程的 DPI 状态。实现依据为 [Microsoft NotificationIcon 示例](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/Win7Samples/winui/shell/appshellintegration/NotificationIcon/NotificationIcon.cpp) 和 [Microsoft 混合 DPI 上下文说明](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-improvements-for-desktop-applications)。

先接入反例时，旧定位逻辑在隐藏面板点击点、负屏坐标和原点三项失败；修复后 x64/x86 的 8 项事件、10 项锚点/回退及 3 项实际线程 DPI 检查全部通过。该夹具不打开真实菜单；后续用户安装 0.1.1 后已确认菜单位置正常。

同协议升级另发现 v8 后台可能仍沿用上一安装版本。现在安装前捕获旧进程 PID 和创建时间，成功安装后复核程序路径、用户、会话及管道所属进程，只向该旧进程发送协作停止事件，并暂时持有旧单实例对象防止停止事件误作用于替换进程。不会执行旧目录程序或终止其他应用。最后核验实际管道所属进程来自新安装目录；不将一次启动请求等同于新版已经接管。每个等待均有 10 秒上限；若旧组件在交接间隙重新启动旧后台，最终核验会报告配置未完成，不静默成功。

相关 x64 构建和隔离回归通过：旧 v2–v7 停止且 v8 不受无条件广播影响；同协议旧后台协作退出；PID、创建时间、路径、用户、会话不符时拒绝；旧进程退出后屏障仍有效；新管道所属程序核验；旧快照重放不影响新版。夹具使用随机对象和合成进程，没有停止生产后台；后续 0.1.0 到 0.1.1 的真实交接已核对新版运行路径及管道归属通过。

## 0.1.3 重复安装与修复注册

用户截图显示 0.1.2 重复安装时，已经属于言舟的词库目录被“目录已有文件”一律拒绝。普通用户数据准备和管理员机器安装原先均没有同包重用分支；只取消其中一层拒绝不能解决问题。
