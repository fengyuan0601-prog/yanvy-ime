## M0：已有内容的使用边界

已有测试覆盖真实五笔和拼音短语候选、上屏、退格、取消、切换及部分文件/网络检查。命名 translator 等配置绕过已完成开发修复并加入反例，后续必须保留受信任文件清单、实际生效配置与组件检查。当前只支持固定离线方案，不支持任意用户配置或脚本；这不构成对恶意操作系统的隔离保证。当前拼音测试没有完整长句质量样例。报告中的网络观察含本地 `AF_UNIX` 查询尝试，未观察到 IP 通信，不应表述为“从未调用任何socket”。

保持源码、数据锁和报告可追溯。后续改动需要复核受影响的功能，不必为了凑通过数重复无关测试。

## M1：Windows 实际打通

### 实施顺序

1. 在 Windows 工具链中编译当前 `core/CMakeLists.txt`，明确 SDK、CPU 架构、运行库和 DLL 部署路径。
2. 固定一个可追溯的 Weasel 上游版本，评估并复用其 TSF 接入及必要候选窗代码；许可、来源和修改记录随工程保留。
3. 将当前核心的候选/提交接口、限定方案与创建会话前的隐私检查接入真实输入生命周期。现有 `Engine` 按进程管理全局 Rime 状态，不可无审查地为每个输入框重复初始化或销毁全局引擎。
4. 实现系统注册、启用引导、候选显示与焦点处理。注册和卸载路径互相对应，不强改用户默认输入法。
5. 在 Windows 原生文本控件和浏览器文本框完成五笔、拼音、选择、取消、中英切换的真实操作。

### 关口

必须有 Windows 构建日志、系统可选择的输入法、实际应用输入记录。仅 Linux 测试、交叉编译成功、DLL 生成或自建文本框演示，都不能标记 M1 完成。

原生机制依据：[Microsoft IME 要求](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements)；复用候选：[Weasel](https://github.com/rime/weasel)。

## M2：Windows 日用质量

| 测试维度 | 必须包含的场景 |
| --- | --- |
| 应用 | 记事本类原生控件、Edge/Chrome、Word或WPS、常用聊天软件、至少一个32位应用 |
| 编辑 | 数字选词、翻页、退格、Esc、Enter、选中替换、光标移动、换行、连续提交 |
| 焦点 | 多窗口切换、未上屏时失焦、应用退出、切到另一输入法、休眠恢复 |
| 文字 | 五笔重码、简码、满码行为、常用词、较长拼音、数字、英文、标点、网址邮箱 |
| 显示 | 100%/150%/200%缩放、多显示器、窗口边缘、深浅色、较大字号 |
| 异常 | 不存在或损坏的词库、配置损坏、引擎初始化失败、权限不足、重复启动 |

密码和敏感输入框遵守系统提供的状态；不靠读取正文去猜是否敏感。默认无学习原则覆盖所有输入框。兼容性失败应修复或明确记录限制，不能通过抓取全局按键或绕过平台权限补救。

录入质量用固定的人工编写样例测试，不收集用户真实聊天或办公正文。保留样例、预期行为、结果与运行环境。

## M3：Windows 首发交付

交付内容必须同时包括：

- 实际安装包及版本号、SHA-256；未签名则明确标注，签名密钥不得进仓库。
- 对应源码提交、构建步骤、依赖版本与第三方许可。
- 在干净 Windows 环境完成的安装、启用、输入、升级和卸载证据。
- 最终发布构建的权限/依赖检查、正文日志检查、真实输入及空闲时的网络观察。
- 已知限制、问题反馈方式和安全问题反馈入口；反馈模板提醒用户不要贴密码、真实私密输入或完整个人词库。

首次发布不需引入统计后台、自动崩溃上传或账号系统。GitHub Release 下载和用户主动查看网页的流量，与输入程序的自发网络通信分别说明。

## M4：Android 首版

按 [Android 官方输入法接口](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method) 实现原生键盘。可复用 [Trime](https://github.com/osfans/trime) 的合适部分，遵守实际版本许可，去掉不需要的网络、同步、插件与历史记录入口。

首批为26键全拼、五笔86、英文/数字/符号页、候选展开与基本设置。关口包含：普通和密码输入框切换、横竖屏、键盘显示/收起、应用切换、内存回收重启、快速连续按键。验收合并 Manifest 无 `INTERNET`、无输入内容经外部组件传递、无正文自动备份。取得可安装 APK 不等于手机日用完成。

## M5：iOS 首版

使用 Swift 原生键盘扩展，`RequestsOpenAccess=false`。先在不开完全访问的条件下验证内置词库、输入与基础设置，再解决容器 App 和扩展的配置边界。先采用经过核验的依赖；不要把 Windows/Android 的 GPL 前端代码直接复制到 iOS 后声称换一个顶层 MIT 文件就能发布。

关口包含：实机快速输入、扩展恢复、内存压力、系统安全键盘接管与恢复、下一键盘切换、26键全拼/五笔一致性。iOS 系统限制不应冒称产品故障，也不能为了掩盖限制要求完全访问。

依据：[Apple 完全访问说明](https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard)、[键盘扩展限制](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html)、[发布协议](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)。

## M6：按实际需求扩展

优先顺序：手机九宫格 → 拼音纠错与离线词库质量 → 五笔反查和明确可切换的混输 → 98/新世纪五笔 → 双拼与手动短语。

九宫格必须单独完成数字序列到多种音节的消歧、拼音段选择、撤回、候选展开与错误恢复，且复用离线策略。引入任何新词库、方案或插件前先记录来源、许可和输入记录行为。可选本地学习不是当前承诺的已实施功能；如未来提出，先说明本机会保存什么、如何清除、备份怎样处理，默认保持关闭。
