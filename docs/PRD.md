最新交付快照（2026-10-30）：0.1.5 Windows 正式版已交付，用户已安装确认；本机 74 项固定文件核对通过。当前实现与验收边界见 [正式交付确认](RELEASE-0.1.5-ACCEPTANCE.md) 和根 README。下列 2026-10-26 阶段状态作为原始规划及历史证据保留，后续沿用既有路线继续。

版本：规划 v0.1｜日期：2026-10-26｜维护方式：个人维护、GitHub 开源。

## 1. 产品目标

言舟是一款五笔、拼音共存的本地输入法。用户在电脑和手机上使用同一套品牌与输入习惯，输入内容只为完成当前输入在本机处理。官方版本免费、无广告、不采集用户输入或使用行为，不建立云端用户画像。

首个交付目标是**可安装、可在真实应用中长期使用的 Windows 输入法**。Android、iOS 都纳入产品路线，分别使用系统原生输入法接口；当前工程的命令行核心不等同于任何平台的成品输入法。

产品质量要求（2026-10-30 更新）：外观漂亮、UI 精致、整体有质感是第一产品优先级。从功能结构、页面布局和核心流程开始按最终成品标准设计，沿用已认可的言舟品牌；候选窗、设置、输入方案选择、中/英入口、安装与升级界面都必须保持一致的设计品质。视觉设计达标、核心交互顺畅、功能正确稳定三项共同构成项目完成标准，隐私约束继续有效。通过精简默认项让普通用户安装后即可打字，同时保留必要的五笔设置。具体执行根目录 AGENTS.md 中的“所有软件统一执行的设计与开发要求”。

## 4. Windows 首发功能

| 功能 | 首版要求 | 验收重点 |
| --- | --- | --- |
| 系统接入 | 原生 TSF 输入法，可通过系统输入法切换器选择 | 在其他应用内真正输入，不依靠自建文本框演示 |
| 五笔86 | 单字、词组、简码、候选翻页、数字选词、空格确认 | 重码顺序稳定，满码上屏行为明确，不误吞按键 |
| 全拼 | 完整拼音、常用短语、分段选词、基础整句转换 | 建立含多音字、中英文混排的离线样例，不以两个词替代整句验收 |
| 中英切换 | 中/英、五笔/拼音状态清楚，切换键可设置 | 不抢占应用快捷键，未完成编码如何处理有一致规则 |
| 编辑操作 | 退格、删除、Esc取消、Enter、方向移动与选词 | 不重复上屏、不丢字、不把上一窗口组合串送入下一窗口 |
| 标点与数字 | 中文/英文标点、数字、日期和常见符号 | 网址、邮箱、密码字段不被不合适的转换干扰 |
| 候选窗 | 跟随输入位置，浅色/深色，可调字号 | 多屏、缩放、边缘位置、输入框移动后不遮挡或失联 |
| 本地设置 | 输入方式、按键、候选数、字号、颜色 | 保存后生效，损坏配置可恢复默认，不保存输入历史 |
| 安装维护 | 安装、升级、卸载、恢复可用的系统输入方式 | 不强改系统默认输入法，不破坏已有输入法和用户配置 |

五笔的“四码唯一候选直接上屏”“下一键顶屏”需作为不同规则处理，先以可解释的默认行为完成验证，再允许用户调整。纯五笔应保持纯形码体验；拼音反查和五笔拼音混输可后续增加，不能在首版默认混合候选造成顺序跳动。

首版只提供只读内置词库。手动短语、自定义词库与可选本地学习各自属于后续功能，不能以“提升体验”为由提前恢复输入历史记录。离线词库更新随软件版本提供，不静默下载新内容。

## 5. 手机产品范围

两种手机系统都使用独立原生前端，共享经过核验的引擎、输入方案和测试样例，不假设能够直接复用 Windows 界面。

### Android

通过 `InputMethodService` 和输入连接提交文本，采用 Kotlin 原生界面与必要的 C++/JNI 连接。可评估复用同文前端，实际引入部分保留 GPL 条款。平台接口依据见 [Android 官方输入法开发说明](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)。

先完成26键全拼、五笔86、英文/数字/符号页、候选展开、长按删除、键盘切换、横竖屏和键盘高度。九宫格随后单独实现音节消歧、候选选择、误触处理与编辑，不能宣称当前已支持。触感、按键音、单手模式可在基本输入稳定后加入。

产品目标是不声明 `INTERNET` 权限；同时检查合并后的 Manifest、依赖、外部 Intent 和导出组件，防止其他路径传递输入内容。用户词典和输入相关缓存不得被自动云备份；具体备份排除规则必须以最终 Android 构建及系统版本实测。

### iOS

采用 Swift 原生 Custom Keyboard Extension，连接本地引擎。**首版不请求“允许完全访问”，配置 `RequestsOpenAccess=false`。** 内置词库、核心选词与必要设置应在这一条件下可用，不能将“开启完全访问”作为安装步骤或功能解锁条件。容器 App 的配置传递、文件导入和扩展内存限制须先做小规模实机验证，再确定支持范围。依据见 [Apple 开放访问说明](https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard)。

安全输入框、部分电话号码输入框或拒绝第三方键盘的 App 可能使用系统键盘，应将正常切换与恢复列入验收。不可承诺覆盖所有输入框。依据见 [Apple 自定义键盘文档](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html)。

iOS 首批同样先做26键全拼和五笔；九宫格在基本输入稳定后跟进。是否能通过 App Store 分发，以实际依赖许可、签名构建和审核结果为准，不能以“源码已经公开”代替这些要求。

## 6. 隐私与无广告要求

以下是产品约束；当前开发验证与独立复核状态见第3节，不能表述为所有平台的约束已经实现并通过验收。

1. **输入只在本机处理。** 只接触当前输入会话所需的编码与必要上下文，不主动扫描文档、通讯录、应用列表或剪贴板，不做全局键盘监听。
2. **不建立用户档案。** 没有账号、设备追踪标识、使用统计、广告 SDK、行为分析或输入内容上报。
3. **首版不自动记忆。** 不保存词频学习、输入历史或自动剪贴板历史；会话结束和焦点变化正确清理临时组合状态。
4. **日志不含正文。** 允许记录必要的版本号与错误类别，但不能包含按键串、候选、提交文字、周边文本或完整内存转储。调试功能必须明确限定在开发构建。
5. **输入程序不主动联网。** 首版不做后台更新检查、云候选、在线翻译或在线语音。用户通过浏览器或应用商店主动取得软件版本。
6. **数据文件与代码分开。** 词库导入若后续开放，只接受明确的数据格式；不默认运行外部 Lua、命令、网络资源或任意插件。
7. **验证针对发布构建。** 要有最终权限清单、依赖清单、真实输入时的文件和网络检查。有限场景“未观察到流量”不能写成全系统或全部未来版本的安全证明。

隐私承诺限定于言舟官方软件自己的处理和传输行为。接收文字的应用、操作系统、用户主动打开的网站及商店有各自的数据处理；言舟不能替它们承诺不留存数据。

## 7. 赞助与品牌露出

核心功能完全免费。关于页可以有“支持开发”和“其他作品”入口，由用户主动打开；候选窗、键盘、首次上屏和设置保存流程中没有弹窗、推荐位或赞助提示。赞助不换取词库、速度、隐私等级等差别待遇。

输入进程不得携带当前输入内容打开外部网页。手机赞助入口应先按目标商店的实际规则安排；没有完成该核验前，不加入绕过商店支付规则的入口。官方产品原则约束官方发行与 PR 合并，不能向标准开源许可证添加“所有第三方分支禁止商业使用”等限制。

## 8. 技术与开源边界

公共输入核心优先使用 [librime](https://github.com/rime/librime)。Windows 通过 TSF 接入；可复用审查后的 [Weasel](https://github.com/rime/weasel) 接入和候选窗代码，保留对应 GPL 义务。Windows 系统要求以 [Microsoft 官方 IME 文档](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements) 为准。

当前原创 `core/`、脚本与补丁标注 BSD-3-Clause；上游原文件的许可证继续有效。当前词库及配置来源、提交号、哈希记录在 [manifest.lock.json](../third_party/manifest.lock.json)。当前引入资料包括 [五笔86](https://github.com/rime/rime-wubi)、[简体拼音](https://github.com/rime/rime-pinyin-simp)、[基础配置](https://github.com/rime/rime-prelude) 和 [笔画反查依赖](https://github.com/rime/rime-stroke)，不能统称“全部 BSD”。

Android 若复用 [Trime](https://github.com/osfans/trime)，按引入版本履行许可。iOS 原创代码可单独选择宽松许可，但这不能覆盖移入的 GPL/LGPL 代码或数据；逐项核实最终分发包。Apple 要求遵守第三方开源许可且与分发条款相容，见 [Apple 开发者协议](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)。

## 9. 验收原则

- 视觉与交互：实际运行发布候选构建，检查主要页面、候选窗、设置和安装维护核心流程，以及正常、空、加载、成功、失败、悬停、焦点、选中、禁用等适用状态；在目标窗口尺寸和缩放下排除错位、拥挤、截断、风格不一致与操作不顺。交付代表性真实运行截图，关键动效或连续交互附简短演示，明确已检查范围和未验证部分。
- 完成标准：视觉设计、核心交互、功能正确稳定必须共同达标；功能通过不能替代视觉质量验收。
- 正确性：真实应用输入、编辑、切换和多窗口流程中，不丢字、不重复上屏、不误提交未完成内容。
- 稳定性：连续输入、休眠恢复、输入法切换、应用退出和重开后可继续使用；失效可切回系统输入法。
- 体验：用固定文本样例记录五笔重码、拼音选词及长句表现；性能在指定设备上记录冷启动、热输入候选延迟、内存和手机耗电，尚未测量的数值不作达标宣称。
- 隐私：最终发布构建默认无学习，无正文日志，无自发 IP 外联；检查路径涵盖安装、初次启动、输入、切换、空闲和升级后的首次运行。
- 交付：源码提交、依赖锁定、安装包、对应哈希、许可证和已知限制匹配；测试报告须区分 PASS、FAIL、BLOCKED、NOT RUN。

## 10. 首版暂不加入的功能
