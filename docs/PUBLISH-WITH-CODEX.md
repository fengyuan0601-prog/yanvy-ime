## 先完成源码上传

1. 定位解压后的 `yanvy-ime` 工程根目录，先读 `AGENTS.md`、`README.md`、`LICENSING.md` 和 `docs/EXECUTION-REPORT.md`。
2. 检查本机 Git/GitHub 的真实登录状态与远程仓库状态。用户已经创建仓库，不再创建同名仓库。当前 ChatGPT 连接曾收到写入403；这不是成功推送记录。
3. 使用用户已合法授权的 Git 客户端上传。若本机确实未登录，通过正常安全登录流程完成；只在账号认证或新增必要权限需要用户本人操作时说明具体原因。不要让用户把密码、访问令牌或验证码发到聊天里。
4. 将当前源码、图标、配置、词库、许可证、文档和 `.github` 工作流放在仓库根目录。源码包省略 `.git`；若本地尚无仓库，可在独立工作目录克隆目标仓库后复制本工程内容，保留新克隆的 `.git`。如果本地已经有 Git 历史，先核对工作树和远程地址再决定操作，不能把无关父目录当作本项目提交。
5. 不提交 `core/build`、临时依赖、用户词库、日志、密钥或外层ZIP。保留 `.gitattributes` 的LF规则，不改动受信词库文件的字节或许可证。`SOURCE-COMMIT.txt` 是本地快照说明，不是远程发布证明。
6. 若远程仍为空，正常提交并推送 `main`。若远程已有内容，先获取和比对，保留维护者改动并合理合并；禁止强制覆盖。不要为了绕过权限错误而删除工作流或隐私检查。
7. 核对远程最新提交、README、图标及主要目录均已上传，查看 GitHub Actions 的实际结果。构建或检查失败时修复具体问题再推送，不将本地报告改写成远程通过记录。
8. 将最终仓库链接、提交SHA、CI真实状态，以及仍未完成的平台接入清楚报告给用户。当前只发布开发源码，不标成稳定版，不伪造 Windows 安装包、APK 或 iPhone App。
